# Dependency lock regeneration

This record lists the command that regenerates each committed lock file, and
the CI check that fails when a lock differs from that command's output. Use it
to repair a Dependabot pull request, or to update a dependency by hand. Issue
[#1361](https://github.com/thekaveh/VMx/issues/1361) records why these checks
exist.

## 1. Regeneration commands

Run each command from the repository root.

| Ecosystem  | Lock files                                                              | Regeneration command                                                                                                                                                  |
| ---------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NuGet      | `langs/csharp/**/packages.lock.json`                                    | `dotnet restore langs/csharp/VMx.sln --force-evaluate`                                                                                                                |
| NuGet      | `examples/csharp/avalonia/*/packages.lock.json`                         | `dotnet restore <project>.csproj --force-evaluate` for each Avalonia project                                                                                          |
| uv         | `langs/python/uv.lock` and each `examples/python/**/uv.lock`            | `uv lock --project <directory> --upgrade-package <package>==<version>`, with the uv version that the workflows pin in their `setup-uv` steps                          |
| pip (docs) | `docs/requirements.txt`                                                 | The command in the file's header: `uv pip compile docs/requirements.in --python-version 3.12 --generate-hashes --output-file docs/requirements.txt`, with the same uv |
| npm        | `package-lock.json` next to each `package.json` that Dependabot updates | `npm install --package-lock-only --ignore-scripts --prefix <directory>`                                                                                               |
| Cargo      | `Cargo.lock` next to each `Cargo.toml` that Dependabot updates          | `cargo update --manifest-path <directory>/Cargo.toml -p <crate> --precise <version>`                                                                                  |

A uv lock that a newer uv wrote keeps its newer lock revision when the pinned uv
runs `uv lock`. To repair it, restore the lock from the base branch first, then
run the uv command with the pinned uv.

## 2. CI checks

| Defect                                                          | Check                                                                                                   |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| A NuGet lock file lost a target-framework section (`NU1004`)    | `tools/tests/test_csharp_runtime_dependency_contracts.py` compares each lock with the project's targets |
| A NuGet lock file differs from `Directory.Packages.props`       | The same test compares every central package in each lock with its pin                                  |
| One package of the .NET servicing family moved alone (`NU1109`) | The same test names the family members that differ                                                      |
| A newer uv wrote a `uv.lock`, or `uv lock` rewrites it          | `tools/check-dependency-locks.py` in the conformance workflow                                           |
| `docs/requirements.txt` differs from its header command         | `tools/check-dependency-locks.py` in the conformance workflow                                           |

Each failure message names the regeneration command. The four .NET servicing
packages are `Microsoft.Bcl.AsyncInterfaces`,
`Microsoft.Extensions.DependencyInjection.Abstractions`,
`System.Collections.Immutable`, and `System.Text.Json`. The `dotnet-servicing`
group in `.github/dependabot.yml` moves them in one pull request.

## 3. Limits

- GitHub gives workflows on Dependabot pull requests a read-only token. The
  checks therefore fail fast and name the command. They do not push a
  regenerated lock.
- `tools/check-dependency-locks.py` needs network access to the package index.
  It restores each committed file after it compares the regenerated bytes.
